# Electronic Diary — руководство: запуск и устройство программы

Электронный дневник для школ: оценки, расписание, посещаемость, задания, новости, опросы, жалобы,
меню столовой и уведомления. Одна установка обслуживает много школ, и каждая видит только свои данные.
Интерфейс на двух языках — русском и кыргызском.

**Стек:** Java 17 · Spring Boot 3.5 · Spring Security + JWT · PostgreSQL 17 · Flyway · Hibernate · Thymeleaf + обычный JavaScript.

## 1. Быстрый запуск

### Что нужно установить

| Программа | Версия | Зачем |
|---|---|---|
| JDK | 17+ | сборка и запуск приложения |
| Docker + Docker Compose | 20.10+ / 2.0+ | база данных PostgreSQL в контейнере |
| Maven | не нужен отдельно | в проекте есть `./mvnw` |

### Шаги

```bash
# 1. Файл настроек
cp env.example .env
# откройте .env и заполните как минимум DB_PASSWORD и JWT_SECRET (см. раздел 2)

# 2. База данных (PostgreSQL на порту 5434)
docker compose up -d

# 3. Приложение (порт 8088)
set -a; . ./.env; set +a
./mvnw spring-boot:run
```

Откройте **http://localhost:8088** — это главная страница. Вход: **http://localhost:8088/login**.

При каждом запуске Flyway сам применяет новые миграции к базе (папка `src/main/resources/db/migration`).
Hibernate работает в режиме `validate`: если структура базы не совпадает с кодом, приложение не запустится и
скажет, что именно не так.

### Сборка JAR для сервера

```bash
./mvnw clean package -DskipTests
set -a; . ./.env; set +a
java -jar target/school-*.jar
```

### Если Docker не запускается

На Linux служба Docker может быть остановлена: `sudo systemctl start docker`.

## 2. Переменные окружения (.env)

Файл `.env` лежит в корне проекта и **не попадает в git** (он в `.gitignore`).

| Переменная | Обязательна | Что это |
|---|---|---|
| `DB_PASSWORD` | да | пароль пользователя `developer` в PostgreSQL |
| `JWT_SECRET` | да | секрет подписи токенов входа, **не короче 32 символов**. Без него приложение не запустится. Смена секрета разлогинивает всех |
| `MAIL_HOST` | для писем | SMTP-сервер, например `smtp.gmail.com` или сервис рассылок (Brevo, Amazon SES) |
| `MAIL_PORT` | нет | по умолчанию `587` |
| `MAIL_USERNAME`, `MAIL_PASSWORD` | для писем | логин и пароль SMTP (для Gmail — «пароль приложения») |
| `MAIL_FROM` | нет | адрес отправителя, по умолчанию `MAIL_USERNAME` |
| `MAIL_SMTP_AUTH`, `MAIL_STARTTLS` | нет | по умолчанию `true`; для локального тестового сервера ставят `false` |
| `APP_PUBLIC_URL` | желательно | адрес сайта для ссылок в письмах, например `https://diary.school.kg` |
| `OPENAI_API_KEY` | нет | ключ OpenAI (см. «ИИ-модули» в разделе 6 — сейчас внешний ИИ отключён) |

**Без почты** приложение работает, но не будут работать: импорт учеников и учителей, выдача временных паролей
и «Забыли пароль?». Вместо них будет понятное сообщение «Почта не настроена». Пароль при этом можно задать вручную
в форме создания пользователя.

Для рассылки нужны и домен, и сервис: домен — адрес отправителя (`noreply@diary.kg`), сервис — то, что отправляет
письма. Обычный Gmail ограничен примерно 500 письмами в день, для школы этого мало. У домена нужно настроить
записи SPF/DKIM, иначе письма с паролями попадают в спам.

## 3. Первая школа: от регистрации до первого входа

1. **Регистрация** — страница `/pricing` («Регистрация» в меню). Регистрация бесплатная: указываются только
   название школы, контактная почта и, по желанию, телефон.
   Система создаёт школу и показывает **пароль школы** (код активации) — его нужно сохранить.
   Название школы превращается в «адрес» (slug): «PLIT 99» → `plit-99`. Две школы с одинаковым адресом создать нельзя.
2. **Активация** — страница `/activate`. Вводится пароль школы и данные первого администратора.
   Пароль администратора = пароль школы.
3. **Первый вход** — `/login`: название школы (`plit-99`), почта администратора, пароль школы.
   Система **сразу попросит сменить пароль** — код активации выдан системой и больше не используется.
4. Дальше администратор создаёт классы, предметы, загружает учеников и учителей из Excel (раздел 8).

## 4. Как устроена программа

### Слои

```
Браузер (Thymeleaf-страницы + JS)
   │  fetch /api/{школа}/...  с заголовком Authorization: Bearer <JWT>
   ▼
JwtAuthenticationFilter  — проверяет токен, школу, роль, временный пароль; выставляет текущую школу
   ▼
Контроллеры (controller/)  — URL, проверка роли через @PreAuthorize, приём JSON
   ▼
Сервисы (service/)  — вся бизнес-логика и проверки (раздел 6)
   ▼
Репозитории (repository/)  — Spring Data JPA
   ▼
Hibernate  — автоматически добавляет «school_id = текущая школа» в каждый запрос
   ▼
PostgreSQL
```

Страницы (`/plit-99/admin`, `/plit-99/student`…) отдаются всем — это просто HTML. Защищены **данные**:
каждый запрос к `/api/**` требует токен, и сервер сам решает, что этому пользователю можно.

### Путь одного запроса

На примере «ученик открывает свои оценки» (`GET /api/plit-99/students/me`):

1. JS берёт токен из `sessionStorage` и отправляет запрос через `apiFetch` (`static/js/api.js`).
2. `JwtAuthenticationFilter`:
   - проверяет подпись и срок токена;
   - проверяет, что токен выдан **после** последней смены пароля (иначе — 401, вход заново);
   - проверяет, что школа в адресе (`plit-99`) совпадает со школой в токене (иначе — 403);
   - проверяет, что пользователь всё ещё состоит в этой школе;
   - если пароль временный — пропускает только смену пароля (иначе — 403 `PASSWORD_CHANGE_REQUIRED`,
     и фронтенд переводит на страницу смены пароля);
   - записывает id школы в `TenantContext`.
3. Spring Security проверяет `@PreAuthorize("hasAuthority('STUDENT')")` на методе контроллера.
4. `StudentService.getCurrentStudent()` находит ученика по пользователю.
5. Hibernate достаёт ученика и его оценки, **добавляя к SQL условие `school_id = <id школы>`**.
6. Ответ — JSON; JS рисует страницу, экранируя данные через `esc()`.

### Изоляция школ (multi-tenancy)

- Все школьные таблицы (классы, ученики, учителя, родители, предметы, оценки, расписание, посещаемость,
  курсы, задания, новости, опросы, жалобы, меню, уведомления) содержат колонку `school_id`.
- В сущностях это поле помечено `@TenantId`. Hibernate сам:
  - подставляет текущую школу при сохранении;
  - добавляет фильтр по школе в **каждый** запрос, включая `findById`.
- Текущая школа берётся из `TenantContext` → `SchoolTenantResolver`. Без токена школа = `-1`,
  то есть запрос не видит ничего.
- Пользователи (`users`) — общие: один человек может работать в нескольких школах (таблица `user_schools`).
  Поэтому всё, что касается пользователей, проходит через `CurrentSchoolService`.
- **Ограничение:** нативный SQL фильтром не покрывается. Если появятся нативные запросы, школу нужно учитывать вручную.

### Безопасность

| Механизм | Где |
|---|---|
| Пароли хранятся только как хэш BCrypt | `SecurityConfig` |
| Вход — JWT на 24 часа, секрет из `JWT_SECRET` | `JwtService` |
| Смена пароля отзывает все старые токены (точность — миллисекунды) | `User.setPassword`, `JwtService.isTokenValid` |
| Проверки ролей на каждом методе API | `@PreAuthorize` в контроллерах |
| Временный пароль: до смены доступна только смена пароля | `JwtAuthenticationFilter` |
| ФИО — только буквы, пробел, дефис, апостроф, точка | `PersonNames` |
| Данные с сервера вставляются в HTML только через `esc()` / `escJs()` | `static/js/safe-html.js` |
| «Забыли пароль?» — одноразовая ссылка, в базе хранится только её хэш | `PasswordResetService` |
| Логины (email) уникальны без учёта регистра | индекс в V32, `CurrentSchoolService.setEmail` |

**Правило для нового кода:** если данные с сервера вставляются в страницу через `innerHTML`,
их нужно оборачивать в `esc(...)`, а внутри `onclick="..."` — в `escJs(...)`. Иначе возвращается XSS.

### Ошибки

| Ситуация | Ответ |
|---|---|
| Ошибка ввода (`IllegalArgumentException`, `IllegalStateException`) | 400 с текстом |
| Нет прав (`SecurityException`, `@PreAuthorize`) | 403 |
| Ошибки валидации DTO | 400 со списком полей |
| Конфликт в базе (дубликат, связанные данные) | 409 «Такая запись уже существует…» |
| Битый JSON, буквы вместо числа | 400 «Некорректные данные в запросе» |
| Токен истёк или отозван | 401 → фронтенд ведёт на `/login` |

### Два языка интерфейса

- Страницы написаны на русском. Переключатель «Русский / Кыргызча» — в правом верхнем углу, выбор запоминается в браузере.
- Перевод делает `static/js/i18n.js` по словарю `static/js/i18n-ky.js` прямо в браузере: текст, подсказки в полях,
  заголовок вкладки, `alert`/`confirm`, даты и всё, что JS дорисовывает позже.
- Данные школы (названия классов, предметов, имена) не переводятся — их школа вводит сама на нужном языке.
- Письма с паролями приходят на двух языках сразу.
- Как добавлять переводы — раздел 9.

## 5. Роли и доступ

| Роль | Что делает |
|---|---|
| **ADMIN** (администратор) | управляет всем в своей школе: пользователи, классы, предметы, курсы, расписание, новости, опросы, импорт, настройки оценивания |
| **DIRECTOR** (директор) | почти всё, что администратор, кроме управления администраторами; видит жалобы и аналитику |
| **TEACHER** (учитель) | ставит оценки по своим предметам, отмечает посещаемость **своих** уроков, создаёт задания (меняет и удаляет только свои), публикует новости. Классный руководитель (куратор) создаёт и редактирует учеников **только своего класса** и может выслать им новый пароль |
| **STUDENT** (ученик) | видит свои оценки, расписание, посещаемость, задания, курсы (записывается сам), голосует, пишет жалобы. **Не может менять своё ФИО** |
| **PARENT** (родитель) | видит детей: оценки, посещаемость, задания. Один аккаунт на всех детей |
| **MINISTRY** (министерство) | видит жалобы и меню. Сейчас ограничено одной школой — отдельного режима «по всем школам» нет |

## 6. Сервисы — подробно

Все сервисы лежат в `src/main/java/com/education/school/service/`.

### Школа и пользователи

#### `SchoolOnboardingService` — регистрация и активация школы
- `calculatePrice(...)` — всегда 0: регистрация школы бесплатная (метод оставлен для совместимости `/api/purchase/calculate`).
- `createSchoolAccount(request)` — создаёт школу: название → slug, проверка уникальности, генерация пароля школы (хранится только хэш).
- `completeSchoolRegistration(request)` — по паролю школы создаёт первого администратора, привязывает его к школе и делает директором школы в карточке. Повторная активация запрещена; почта проверяется на уникальность. Администратор обязан сменить пароль при первом входе.

#### `CurrentSchoolService` — «текущая школа» для пользователей
Школьные данные фильтруются Hibernate автоматически, а пользователи общие — поэтому все операции с ними идут здесь.
- `getId()` / `get()` — школа текущего запроса (ошибка, если школы нет).
- `attach(user)` — привязать нового пользователя к школе. Без этого он не сможет войти.
- `findUsers()`, `findUsersByRole(role)` — пользователи только этой школы.
- `findUser(id)`, `findUserWithRole(id, role)` — по ID, но только из этой школы и (во втором случае) с нужной ролью — например, через `/directors/{id}` нельзя достать администратора.
- `setEmail(user, email)` — смена логина с проверкой уникальности (понятная ошибка вместо 500).
- `removeUser(user)` — удаление из школы: если человек есть в других школах, его только отвязывают.

#### `UserDeteilsImpl` — загрузка пользователя для Spring Security
`loadUserByUsername(email)` — находит пользователя по почте; если нет — `UsernameNotFoundException`.

#### `PersonNames` — проверка ФИО
`apply(user, имя, фамилия, отчество)` — записывает ФИО после проверки: только буквы любого алфавита
(включая ө ү ң), пробел, дефис, апостроф и точка, до 50 символов. Защита от XSS через имена.

#### `AdminService` — администраторы школы
`findAll`, `findById`, `create`, `update`, `delete`. Работает **только с пользователями роли ADMIN** в текущей школе.
Новый администратор привязывается к школе; если пароль не указан — временный пароль уходит на почту.
Удаление: если человек состоит в других школах — только отвязка.

#### `DirectorService` — директора
То же, что `AdminService`, но только для роли DIRECTOR. Доступен ADMIN и DIRECTOR.

#### `TeacherService` — учителя
- `findAll`, `findAllWithGroup`, `findById` — список учителей (с классом, если учитель куратор).
- `create(request)` — аккаунт + профиль учителя, предметы, классное руководство (если указан класс — учитель становится его куратором). Пароль: указан → обязательная смена при входе; пусто → временный пароль на почту.
- `update(id, request)` — данные, предметы, класс; новый пароль от администратора → обязательная смена.
- `delete(id)` — удаляет профиль и аккаунт. Учителя с выставленными оценками удалить нельзя (база защищает историю оценок).
- `getMyGroupsWithDisciplines()` — для страницы учителя: какие классы и предметы он ведёт (из расписания).

#### `StudentService` — ученики
- `findAll`, `findById`, `getCurrentStudent()` — для ученика: профиль со всеми **неудалёнными** оценками.
- `create(request[, contactEmail])` — аккаунт + профиль. `contactEmail` — почта родителя для ребёнка без своей почты: туда уйдёт пароль. Учитель-куратор может создавать учеников **только в своём классе**.
- `update(id, request)` — учитель меняет только учеников своего класса и не может перевести их в другой класс.
- `resetPassword(id)` — новый временный пароль на почту ученика (или родителя). Старый пароль и все сеансы перестают действовать.
- `deleteById(id)` — удаляет профиль вместе с аккаунтом.

#### `ParentService` — родители
- `findAll`, `findById`, `create`, `update`, `delete` — как у учителей; к родителю привязываются дети.
- `linkToChild(email, имя, фамилия, ребёнок)` — при импорте: родитель уже есть → просто добавить ребёнка (один аккаунт на всех детей); нет → создать аккаунт и выслать ему пароль.
- `getMyChildren()` — дети текущего родителя с оценками.

#### `StudentEnrollmentService` — зачисление ученика из списка
Общая логика для импорта из Excel и ИИ-ассистента. Одна строка — одна транзакция (ошибка → ничего не создаётся, писем нет).
- Есть почта ученика → она и есть логин, пароль приходит ученику.
- Почты нет, есть почта родителя → логин генерируется (`aybek.asanov@plit-99.diary`, кыргызские буквы переводятся в латиницу, однофамильцы получают номер), пароль приходит **родителю**, родитель получает свой аккаунт, привязанный к ребёнку.
- Нет ни той, ни другой почты → строка отклоняется.
- Возраст по умолчанию — по номеру класса (9 класс → 15 лет).

#### `ProfileService` — свой профиль
- `getCurrentUser()` — профиль (для учителя — телефон, о себе, кабинет; для ученика и родителя — телефон).
- `getCuratorProfile()` — для учителя: класс, куратором которого он является.
- `updateProfile(request)` — ФИО (ученику запрещено), логин (с проверкой уникальности), новый пароль (не короче 8), телефон и др. Смена пароля или логина требует войти заново.
- `changePassword(request)` — смена пароля с проверкой текущего; новый не короче 8, не равен текущему и логину. Снимает признак «временный пароль». Контроллер сразу выдаёт новый токен.

### Пароли и почта

#### `PasswordGenerator`
- `generateTemporary()` — временный пароль вида `k7mxp-2qhta`: 10 символов без похожих (0/O, 1/l), криптостойкий генератор.
- `generate()` — пароль школы (UUID) при регистрации.

#### `CredentialMailService` — выдача паролей по почте
- `isConfigured()` / `requireConfigured()` — настроена ли почта.
- `setInitialPassword(user, password)` — для пользователя, которого создаёт кто-то другой: пароль пуст → временный пароль на почту; указан → пользователь обязан сменить его при входе.
- `issueTemporaryPassword(user)` — сгенерировать временный пароль, сохранить хэш, отправить письмо.
- `setPasswordByOther(user, password)` — админ меняет пароль в форме → владелец обязан сменить его при входе.
- `sendPasswordResetLink(user, школа, token)` — письмо со ссылкой «Забыли пароль?».

Как работает отправка:
- письмо уходит **после** успешного сохранения в базе (если сохранение откатилось — письма нет);
- письма отправляются в фоне по одному, импорт не ждёт почтовый сервер;
- адрес: своя почта пользователя или почта родителя (`contact_email`) для ребёнка без почты;
- текст на русском и кыргызском;
- если письмо не дошло — тот, кто создавал аккаунт, получает уведомление «Письмо с паролем не доставлено».

#### `PasswordResetService` — «Забыли пароль?»
- `requestReset(школа, логин)` — создаёт одноразовую ссылку на 1 час и отправляет её. Ответ всегда одинаковый, чтобы нельзя было узнать, существует ли логин. Не чаще одного письма в 5 минут. В базе хранится только SHA-256 токена.
- `resetPassword(token, новый пароль)` — меняет пароль по ссылке (не короче 8, не равен логину), ссылка становится недействительной. **До перехода по ссылке старый пароль продолжает работать** — поэтому чужой логин не позволяет сломать вход.

### Учебный процесс

#### `GroupService` — классы (группы)
`findAll`, `findById`, `create`, `update`, `delete`, `getStudentsByGroupId(groupId)` — классы с куратором, номером, кабинетом, типом финансирования (бюджет/контракт); список учеников класса.

#### `DisciplineService` — предметы
`findAll`, `findById`, `create(name)`, `update(id, name)`, `delete(id)`. У каждой школы свои предметы.

#### `ScheduleService` — расписание
- `findAll`, `create`, `update`, `delete` — уроки: предмет, учитель, класс, дата, номер урока (1–8), время, кабинет.
- Проверки при сохранении:
  - конец урока позже начала;
  - учитель не ведёт два урока одновременно;
  - у класса нет двух уроков в одно время или с одним номером в один день.

  Ошибка объясняет, с каким уроком пересечение.
- `getMyFullSchedule`, `getMyScheduleForToday`, `getMyScheduleForPeriod` — «моё расписание»: ученику — его класса, учителю — его уроки.
- `getScheduleByGroupId(класс, с, по)` — расписание класса за период (для администратора).

#### `MarkService` — оценки
- `create(request)` — только учитель и только по своим предметам; оценка 1–100. Если в этот день у учителя нет урока с этим классом и предметом, **комментарий обязателен** (проверяет и сервер). Ученик и родители получают уведомление.
- `findByGroupAndDiscipline(класс, предмет)` — журнал оценок для учителя (без удалённых).
- `update(id, значение, причина)` — только свои оценки, причина обязательна, значение 1–100; в комментарии сохраняется «Изменено с X на Y».
- `delete(id, причина)` — «мягкое» удаление: оценка остаётся в базе с датой удаления и причиной, но ученик и родитель её больше не видят и в средний балл она не входит.

#### `GradingService` — периоды и итоговые оценки
- `getSettings` / `saveSettings(тип, месяц начала)` — система периодов школы: четверти, полугодия или год; месяц начала учебного года 1–12. Ранее сохранённое некорректное значение не ломает страницу — используется сентябрь.
- `buildPeriods(...)` — расчёт границ периодов («1 четверть 2026/2027» и т. п.).
- `getStudentGrades(школа)` — для ученика: оценки, разложенные по периодам, со средними.

#### `AttendanceService` — посещаемость
- `saveForSchedule(урок, записи)` — отметка по уроку: присутствовал / отсутствовал / опоздал (минуты) / уважительная причина. Проверки:
  - учитель отмечает только **свои** уроки;
  - ученик должен быть из класса этого урока;
  - статус — только из списка.

  Повторное сохранение обновляет отметку; у одного предмета может быть несколько уроков в день.
- `findBySchedule`, `delete` — отметки урока; удаление — с той же проверкой владельца урока.
- `findMyAttendance` (ученик), `findChildrenAttendance` (родитель) — за период.
- `findAllByPeriod`, `findByGroupAndPeriod` — аналитика для администратора и директора.

#### `ExamService` — задания (экзамены, тесты, контрольные, домашние)
- `create` — тип, дата и время, предмет, классы. Ученики классов и их родители получают уведомление.
- `update`, `delete` — учитель меняет и удаляет **только свои** задания; администратор и директор — любые.
- `findForCurrentUser()` — администратор и директор видят все, учитель — свои, ученик — своего класса, родитель — классов своих детей (за последние 2 недели и будущие).

#### `CourseService` — факультативы и кружки
- `create`, `update`, `delete`, `findAll`, `findById` — курсы с учителем (управляют администратор и директор).
- `findAllForStudent()` — курсы с отметкой, записан ли ученик; `enroll` / `unenroll` — запись и отписка самим учеником.
- `findMyCoursesAsTeacher()` — курсы учителя со списками учеников.

### Общение

#### `NewsService` — новости
`findAll`, `findById`, `create`, `update`, `delete`. Публикуют администратор, директор и учителя.
О новой новости получают уведомление все пользователи школы.

#### `PollService` — опросы
- `create`, `update`, `delete` — варианты ответа, активность, роли, которые могут голосовать.
- `findAllForCurrentUser()` — опросы, доступные роли пользователя.
- `vote(опрос, вариант)` — один голос на человека; голосовать можно только ролям, указанным в опросе.

#### `ComplaintService` — жалобы
- `create` — жалоба (анонимная или с именем). Уведомление получают администраторы, директора и министерство **этой школы**. Автор анонимной жалобы хранится, но не показывается.
- `findAll` — для администратора, директора и министерства; `findMy` — свои жалобы; `delete` — «мягкое» удаление, только автором.

#### `NotificationService` — уведомления
- `send(пользователь, тип, заголовок, текст, ссылка)` / `sendToAll(...)` — создать уведомления (оценки, задания, новости, жалобы, недоставленные письма).
- `findMy`, `countUnread` — свои уведомления и счётчик в меню.
- `markRead(id)` — только **своё** уведомление; `markAllRead()` — все свои.

#### `CanteenMenuService` — меню столовой
- `create`, `update`, `delete` — меню на дату, описание, фото (хранится в базе в Base64), классы.
- `findForCurrentUser()` — администратор, директор, учитель, министерство видят все меню; ученик — меню своего класса; родитель — классов детей.

### Импорт

#### `ExcelImportService` — импорт учеников и учителей из Excel
- `preview(файл)` — первые 5 строк и автоматическое сопоставление колонок по заголовкам. Распознаются:
  - для учеников: «ФИО» целиком или раздельные фамилия, имя, отчество; «Почта»; «Почта родителя»; «ФИО родителя»; «Класс»; «Возраст»;
  - для учителей: те же поля ФИО, «Почта», «Предметы», «Телефон».
- `importStudents(запрос)` — импорт; `type = "students"` или `"teachers"`.
  - Ученики идут через `StudentEnrollmentService`.
  - Учителя создаются через `TeacherService`; предметы — через запятую, отсутствующие создаются автоматически.
  - Ответ: сколько добавлено, список имён и ошибки по строкам. Пароли в ответе не возвращаются.
- Поддерживаются `.xlsx` и `.xls`. Пустые колонки не сдвигают сопоставление: колонка без заголовка получает имя «Колонка N».
- Ограничения: файл до 5 МБ, не более 1000 строк и 50 колонок.
- Требует настроенной почты — без неё импорт сразу отказывает и ничего не создаёт.

### ИИ-модули

> **Состояние на момент написания:** над этими модулями сейчас ведётся работа (изменения ещё не закоммичены).
> В текущей версии **внешний ИИ отключён**: данные школы не отправляются в OpenAI, сетевые запросы к нему блокируются
> (`AIConfig`). Ниже описано, что делает каждый модуль, и как он ведёт себя сейчас.

#### `AiAssistantService` — чат-ассистент (кнопка 🤖 справа внизу)
- Задуман как управление школой на естественном языке через OpenAI Function Calling: создание классов, учеников (`add_student`, `add_multiple_students` со списком класса), учителей, предметов, расписания, курсов; анализ успеваемости; удаление учеников и учителей.
- Пароли ИИ не задаёт и не видит — они генерируются сервером и уходят на почту.
- **Сейчас** работает в локальном режиме: на сообщения отвечает подсказкой, а в окне чата есть панель импорта Excel (предпросмотр → импорт), которая использует `ExcelImportService` (адрес `/api/{школа}/ai/files`).

#### `AIAnalysisService` — анализ данных и файлов (страница «AI Анализ»)
- Вопросы об успеваемости по данным школы; разбор файлов: PDF (PDFBox), изображения (распознавание текста Tesseract), Excel.
- **Сейчас** обращение к внешней модели отключено.

#### `SchoolDataGeneratorService`, `AIDataGeneratorService` — генерация демо-данных по описанию
- Создают классы, учителей, учеников, родителей, оценки, расписание со случайными именами — для демонстрации.
- У демо-пользователей пароль равен почте (они не настоящие). Каждый созданный пользователь привязывается к текущей школе.
- **Сейчас** разбор описания через внешнюю модель отключён.

#### `TestDataGeneratorService` — тестовые данные без ИИ
`generateTestData(школа)` — фиксированный набор предметов, классов, учителей, учеников, оценок и новостей. Только для администратора.

## 8. Типовые сценарии

### Загрузить класс из Excel
1. Администратор создаёт класс (Классы → «Добавить класс»).
2. «Импорт Excel» → выбрать «Ученики» → загрузить файл с колонками, например:

   | ФИО | Почта | Почта родителя | ФИО родителя |
   |---|---|---|---|
   | Асанов Айбек Талантбекович | aibek@mail.kg | | |
   | Алиева Айлин | | mama@mail.kg | Алиева Гульнара |

3. Проверить сопоставление колонок, выбрать класс по умолчанию, нажать «Импортировать».
4. Каждый получает письмо со своим логином и временным паролем:
   - Айбек — сам;
   - за Айлин — мама, которая заодно получает свой аккаунт родителя.

   Повторный импорт того же файла дубликатов не создаст: строки с уже занятыми логинами отклоняются.

### Первый вход ученика
Логин и временный пароль из письма → `/login` → система сразу просит придумать свой пароль → дальше обычная работа.
Временный пароль после этого не действует.

### Ученик забыл пароль
- Сам: «Забыли пароль?» на странице входа → школа и логин → ссылка на почту (детям без почты — родителю).
- Через школу: администратор или классный руководитель → список учеников → «✉️ Пароль». Новый временный пароль уйдёт на почту, старый перестанет работать.

### Учитель ставит оценку
«Журнал оценок» → класс и предмет → оценка. Если урока по расписанию в этот день нет — нужно написать причину.
Исправить или удалить оценку можно только свою и только с указанием причины.

## 9. Обслуживание: бэкапы, перевод, обновление

### Бэкап и восстановление базы

```bash
# бэкап
docker exec school-management-system pg_dump -U developer -d school_management_db > backup_$(date +%F).sql

# восстановление (в пустую базу, приложение остановлено)
docker exec -i school-management-system psql -U developer -d school_management_db < backup_2026-10-29.sql
```

Делайте бэкап **перед каждым обновлением**, если в обновлении есть новые миграции.
Бэкапы, сделанные при доработках: `~/electronic-diary-backups/`.

### Добавить перевод на кыргызский

Тексты страниц пишутся на русском; переводы — в `tools/i18n/ky_dict.py`.

```bash
cd tools/i18n
python3 extract.py ../../src/main/resources phrases.json          # собрать все русские фразы интерфейса
python3 build.py . ../../src/main/resources/static/js/i18n-ky.js -v  # собрать словарь и показать фразы без перевода
```

Фразы из списка «без перевода» добавить в `ky_dict.py` и запустить `build.py` ещё раз.
Значки и знаки по краям (`📊 Оценки`, `+ Добавить`) и числа учитываются автоматически.
Переводы стоит вычитать носителю языка.

### Обновление на сервере
1. Бэкап базы.
2. `git pull`
3. Пересобрать и перезапустить приложение — новые миграции применятся сами.
4. Проверить вход и основные страницы.

## 10. Устранение неполадок

| Симптом | Причина и решение |
|---|---|
| Приложение не запускается: `JWT_SECRET must be set...` | в `.env` нет `JWT_SECRET` или он короче 32 символов |
| `Connection refused` к базе | не запущен Docker или контейнер: `docker compose up -d`; база слушает порт 5434 |
| `Schema-validation: missing column ...` | база отстала от кода: проверьте, что миграции применились (`flyway_schema_history`) |
| Вход: «Неверный email, пароль или название школы» | неверная тройка; название школы — это адрес (slug), например `plit-99`. Пользователь может не состоять в этой школе |
| После входа сразу страница «Придумайте свой пароль» | так и задумано: пароль временный (из письма или задан администратором) |
| «Почта не настроена» при импорте или восстановлении пароля | заполните `MAIL_*` в `.env` и перезапустите приложение |
| Письма не приходят | проверьте спам и SPF/DKIM домена; лимиты почтового сервиса; уведомление «Письмо не доставлено» у администратора |
| Внезапно выкинуло на страницу входа | токен истёк (24 часа) или пароль/логин был изменён — это отзывает старые сеансы |
| 403 на запросе | у роли нет прав на это действие, или токен от другой школы |
| 409 «Такая запись уже существует» | дубликат (логин, урок в то же время и т. п.) |
| Часть интерфейса осталась на русском в режиме «Кыргызча» | новая фраза ещё не в словаре — см. раздел 9 |

Логи приложения пишутся в консоль; SQL-запросы — при `spring.jpa.show-sql=true` в `application.properties`.
